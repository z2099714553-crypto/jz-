# 另类历史：按过程而非结果评价决策

## R — 原文 (Reading)

> 我们都不能以成败论英雄，而必须从“假如历史以另一种方式呈现”的另类成本来论断成败。这种以不同方式呈现的历史，我们称之为“另类历史”。
>
> — 塔勒布，《随机漫步的傻瓜》第二章

> 玩俄罗斯转盘赚来的1000万美元，价值不同于靠辛勤努力和娴熟的牙医技术赚来的1000万美元。两者的金额相同，能买相同的东西，但前者的随机成分比后者高。
>
> — 塔勒布，《随机漫步的傻瓜》第二章

> 这么多年来，借由蒙特·卡罗发生器，如果不参考未实现的结果，我无法看懂那些已经实现的结果。我把这叫做“在历史之下求和”。
>
> — 塔勒布，《随机漫步的傻瓜》第三章

## I — 方法论骨架 (Interpretation)

我们只看得到实际发生的那一条历史，但当初做决定时，面对的是一整把"可能发生的历史"。
评价一个决定好不好，要回到做决定的那一刻，问：当时可能出现哪些结果？各自大概多常见？最坏的那几条有多坏？
产生这些结果的机制（作者叫"发生器"）才是评价对象，实际结果只是从中抽出的一张牌。
所以：同样赚 1000 万，靠玩俄罗斯转盘（六条历史里有一条送命）和靠当牙医（重来几千次也差不多）价值完全不同。
同理，一个决定结果不好，不一定是坏决定；结果好，也不一定是好决定。
还要看路径而不只看终点：途中最低点可能已经让人出局。
最后，把"决策质量"和"结果"分成两栏分别写评语，两栏可以不一致。
注意这是一种思考方式，不是精算：现实中发生器看不见，另类历史只能列举和粗估。

## A1 — 书中的应用 (Past Application)

### 案例 1: 牙医戴维与中彩票的门卫马克（思想实验）
- **材料性质**: 思想实验（作者设定的假想邻居），第一章
- **问题**: 中彩票搬进富人区的门卫和隔壁当了 35 年牙医的人，谁更"富有"？
- **方法论的使用**: 让两人的人生各重来很多次：牙医的结果范围很窄（最好在公园大道执业，最差在偏僻小镇）；门卫一百万辈子里几乎每次都是门卫，只有一次中大奖。
- **结论**: 按所有可能人生衡量，牙医比门卫（以及摇滚乐手、投机客）更富有；讨论一个行业要看所有进入者的平均，而不是已经成功的样本。
- **结果**: 原书未说明（思想实验）

### 案例 2: 1000 万美元的俄罗斯转盘（思想实验 + 亲历补充）
- **材料性质**: 赌局为思想实验；作者补充黎巴嫩战争期间一位好友死于此类"游戏"（亲历），第二章
- **问题**: 有人出 1000 万美元请你玩一次俄罗斯转盘，赢家值得赞美吗？
- **方法论的使用**: 六段可能的历史里五段发大财、一段送命；你只看到一段，记者只采访赢家。若一个 25 岁的人每年玩一次，几乎活不到 50 岁；现实中的"枪管"看不见，人们常以"低风险"之名玩着转盘。
- **结论**: 同额财富的"质量"取决于它来自多宽、下限多糟的结果分布。
- **结果**: 原书未说明（思想实验）

### 案例 3: 记者威尔用一次预测失误羞辱希勒（转述）
- **材料性质**: 转述的真实访问（乔治·威尔与罗伯特·希勒），第二章
- **问题**: 希勒说股价过高后股价又涨了一倍，他的判断是否就此失效？
- **方法论的使用**: 区分"预测"（给出概率倾向，属可能出错的一类）与"预言"（断言必然发生）；一次转盘结果不能用来否定一个概率判断。
- **结论**: 希勒对市场理性的见解不因一次预测错误而失效；根据转盘转出的结果抨击或吹捧判断者，是对随机性的无知。
- **结果**: 原书未说明后续

### 合成演练（非原书）: 没去大厂选了国企，现在同学年薪是我两倍
- **问题**: "两年前没去大厂、选了国企，现在大厂同学年薪是我两倍，我是不是选错了？"
- **方法论的使用**: ①识别发生器：当年两条路各自的结果分布 → ②列另类历史：大厂路径里的裁员、35 岁危机、部门被砍；国企路径的稳定下限 → ③看分布宽窄与下限，而不是同学这一条已实现路径 → ④结合当时掌握的信息与自己的偏好判断决策质量
- **结论**: 同学的结果只是宽分布中较好的一条；若当时信息下选择合理，决策并不因此变差。决策质量与结果分两栏写。
- **结果**: 演练，无真实结果（来源：verified.md v02 演练）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要

1. **投资**: 一笔投资赚了/亏了，想知道当初的决定对不对；或被别人用"你看我赚了"证明其做法正确
2. **职业选择**: 后悔当年的选择（没去某公司、没转行、没创业），拿别人的已实现结果对比自己
3. **评价他人**: 以一次成败评价专家、老板、下属、预测者（"他上次说错了，不可信"/"他押中了，是高手"）
4. **日常决策**: 冒险做了某事没出事（酒驾、不买保险、不体检），想以此证明"没问题"
5. **复盘会**: 团队项目结束后做复盘，需要把"运气"和"决策"分开归因

### 语言信号

- "早知道就……" / "要是当初……" / "hindsight", "I should have..."
- "结果证明我是对的/错的" / "the result proves it", "outcome bias"
- "我是不是选错了？" / "Did I make the wrong call?"
- "他上次就说错了，还信他？" / "he was wrong last time"
- "做了这么多次都没事" / "nothing bad has happened so far"

### 与相邻能力的区分

- 与 `luck-vs-skill` 的区别：本卡评价"某一个决定"的质量；`luck-vs-skill` 评价"某人/某段业绩"有多少是能力。
- 与 `ruin-first` 的区别：本卡列另类历史是为了"评价"已做或待做的决定；发现某条另类历史是不可承受的毁灭时，转 `ruin-first` 处理是否该做。
- 与 `hidden-tail-risk` 的区别：后者专门诊断"长期稳定赚钱"背后的隐藏尾部；本卡是更通用的"过程 vs 结果"评价框架。

## E — 可执行步骤 (Execution)

**输入契约**（缺任何一项先问用户，不猜值）：
- 被评价的决定是什么、在什么时间做出
- 做决定时掌握的信息（区分"当时知道"和"事后才知道"）
- 当时可选的方案（至少两个，含"不做"）
- 已实现的结果
- 决策者当时的目标与可承受底线

**输出契约**：
- 另类历史清单：每个方案下列 3–6 条可能路径，标注粗略频率（常见/少见/罕见）与后果（好/一般/差/不可承受）
- 两栏评语："决策质量"一栏、"结果"一栏，分别给评价与理由
- 一句话结论，注明"另类历史为定性列举与粗估，非精算"

**步骤**：

1. **冻结时间点**
   - 做法: 写下做决定那一刻掌握的信息；把事后才知道的信息单独划出，不得用于评价决策质量
   - 完成标准: 两份清单（当时已知 / 事后才知）分开列出

2. **识别发生器**
   - 做法: 说清每个方案产生结果的机制（例如收入由什么驱动、风险从哪里来）
   - 完成标准: 每个方案一句话描述其"结果从哪里来"

3. **列另类历史**
   - 做法: 每个方案列 3–6 条可能路径，至少包含一条好的、一条典型的、一条最坏的；同时写出路径途中的最低点，而不仅是终点
   - 完成标准: 清单完成，每条有频率粗估与后果
   - 判停/跳转: 若任一方案的某条路径后果为"不可承受"（出局、不可逆），先转 `ruin-first` 处理，再回来

4. **比较分布而非单点**
   - 做法: 比较各方案的分布宽窄、下限和典型结果；实际结果放在它所属方案的分布里看它是"常见"还是"少见"
   - 完成标准: 写出"实际结果在其分布中的位置"一句

5. **写两栏评语**
   - 做法: 决策质量 = 当时信息下，所选方案的分布是否符合决策者的目标与底线；结果 = 实际发生了什么
   - 完成标准: 两栏各有评价与理由；若两栏结论不同，明确写出"结果好/坏不改变决策质量评价"
   - 防过度: 若用户已有充足的多次真实结果（重复发生的同类决定），要纳入这些实际记录，不能只谈另类历史

## B — 边界 (Boundary)

### 不适用场景
- 结果已大量重复出现、实际数据充足时，应以实际统计为主，不能只用想象的另类历史
- 需要精确量化的场景（定价、精算）：本卡只做定性列举，不提供概率数字
- 用户需要处理后悔、悲伤等情绪本身时，本卡只是辅助，不替代心理支持

### 作者警告的失败模式
- 结果论：以成败论英雄，"成功者总把成功归因于决策得好"
- 多次侥幸后忘了子弹：试过几十次没事，就以为自己很安全
- 以一次预测结果抨击或吹捧判断者
- 反向错误（作者也警告）：过度随机化——"只见到历史的另类发展，却忽视实际真正发生的事"

### 作者盲点（来自阶段 0 批判）
- 作者用来说明另类历史的塔利波、约翰本身是作者挑选的单一路径故事
- "把随机误当规律的代价更高"未经论证；若一味用"另类历史"为所有坏结果开脱，可能逃避对真实错误的复盘

### needs-review / verified 相关缺口
- 现实中发生器不可见，另类历史只能定性列举、粗估；卡片已在输出契约中要求注明"列举而非精算"（verified.md v02 gaps）

### 与相邻能力的混淆点
- 与 `luck-vs-skill`：一个评价决定，一个评价人；不要用一次决定的好坏判断一个人的能力
- 与 `ruin-first`：列出不可承受路径后，是否做的判断交给 `ruin-first`
